# ガイドブック読みやすさ改善 — 変更内容の共有

**日付**: 2026年10月30日
**対象**: ガイドブック全6章 + 目次ページ

---

## 背景

ガイドブックの読みやすさについて、AIを活用して分析・改善を行いました。全6章を各読者ペルソナ（行政職員、政治家、政党の党員、学生・研究者、市民、エンジニア）の視点からAIに読み込ませて問題点を抽出し、修正案の作成・実装もAIと協働で進めました。その結果、**8つの構造的な問題** を特定し、4段階に分けて修正を行いました。

---

## 分析で見つかった主な問題

### 1. 読者の関心からではなく、内部の経緯から始まっている
- 第1章がSlackの投稿引用（「ガイドブックを作りませんか？」）から始まり、DD2030の活動内容ではなく「このドキュメントが生まれた経緯」が冒頭に来ていた
- 読者が「DD2030とは何か」を知りたくて開いたとき、最初に目に入るのが内部Slackの引用文で、自分に関係ある情報だと認識しにくかった

### 2. 抽象→具体の順序が逆
- 第2章で概念の解説が重ねられ、具体的なプロジェクトや活動に到達するのが第3章以降だった
- 見出し「3つのブロードリスニングの接続としてのコアループ≒2030≒DD」のような数式的表現があった

### 3. 著者の思考過程をそのまま追体験させる構成
- 「ですので、まず…概観しましょう」「ここまでの議論で…明らかになりました」「残すは…です」といった、論文や講義ノートのような展開
- 「ガイドブックの目的①の大部分が達成されました」のようなメタ的自己参照

### 4. 同じ情報の重複
- コアループの定義引用、広聴AIの説明、Slack招待リンクなどが複数章にまたがって重複
- 04章のプロジェクト紹介が03章とほぼ同じ情報だった

### 5. その他
- 第3章がProject Coreloopに偏重（全体の60%以上）
- 第5章が薄く、具体的事例がない
- 専門用語（TTTC, SODP, vTaiwan, Polis等）の説明不足
- 裸のXリンクが5つ並んでおり、読者に何のポストか分からない
- 記事②のURLが記事①と同じになっていた（誤り）

## 実施した変更

### Phase 2: 第1章・第2章の構成改善（最もインパクトの大きい変更）

#### 第1章：DD2030とは何か

| | Before | After |
|---|---|---|
| **冒頭** | Slack投稿の引用（22行） | 「DD2030とは」の一文定義から開始 |
| **構成** | 経緯→5つの取り組み（リストのみ）→コアループ→BL→読者 | DD2030の定義→5つの取り組み（各1行説明付き）→コアループ→BL→読者→経緯（末尾に移動） |
| **文体** | 「まず…概観しましょう」「結論から言えば…」 | 結論先行の平叙文 |
| **5つの取り組み** | 名前だけのリスト | 各項目に1行の説明を追加 |
| **⿻（プルラリティ）** | 説明なし | 「多元的な声を重ね合わせる思想」と注釈 |
| **Slack引用** | 冒頭 | 削除（ガイドブックの目的は本文中で説明） |

**変更理由**: 読者が最初に知りたいのは「DD2030が何をしているか」であり、「ガイドブックがなぜ作られたか」ではない。Slack引用は価値のある情報だが、冒頭にあるべきではない。

#### 第2章：5つの取り組みの関係

| | Before | After |
|---|---|---|
| **冒頭** | 説明なしにいきなり「3つのBL」 | 「この章で何が分かるか」を1行で提示 |
| **見出し** | 「3つのBLの接続としてのコアループ≒2030≒DD」 | 「コアループと3つのブロードリスニングの関係」 |
| **メタ的表現** | 「ガイドブックの目的①の大部分が達成されました」「残すは…です」 | 削除 |
| **長文引用** | 書籍から長文を丸ごと引用 | 要約して短縮、詳細は書籍への参照に |
| **専門用語** | TTTC、Polis、JOINが列挙のみ | 各ツールに1行の説明を追加 |
| **Polimoney** | 言及なし | 「政治資金の透明化を通じて政治参加の基盤を整える」と位置づけを明示 |

**変更理由**: 読者は学術論文を読みに来ているのではなく、DD2030の構造を理解したいだけ。メタ的な進捗報告は著者にとっては意味があるが、読者には不要。

### Phase 3: 表現の改善

| 修正 | 内容 |
|---|---|
| **Xリンクに説明追加** | 5つの裸URLに「前澤友作氏 — 詐欺広告問題への問題提起」等の説明テキストを付与 |
| **SODP正式名称追加** | 「SODP」→「SODP（Stanford Online Deliberation Platform）」 |
| **各章冒頭に要約追加** | 03〜06章の冒頭に「この章で分かること」を1〜2行で追加 |
| **06章GitHubリンク拡充** | 広聴AIのみ → いどばた、Polimoneyも追加 |

**変更理由**: 裸URLは読者にクリックする動機を与えない。専門用語は初見の読者にとって障壁になる。

---

### Phase 4: 重複整理

| 修正 | 内容 |
|---|---|
| **「整備中です」バナー** | 全6章に同じバナーがあったものを目次ページのみに集約。繰り返し表示は読者に「このドキュメントは信頼できないのでは」という不安を与えうる |
| **04章プロジェクト情報** | 03章と重複していた各プロジェクトの説明（広聴AI、いどばた、Coreloop、Polimoney）をリンク付き表形式に集約し、詳細は第3章へリンク |
| **記事②のURL修正** | 記事①と同じURLになっていた誤りを修正（`n56e0610bba18` → `n47ec24c81322`） |

---

### Phase 5: 第5章の充実化

| | Before | After |
|---|---|---|
| **分量** | 約40行 | 約85行 |
| **冒頭** | 要約文と「はじめに」が重複 | 重複を解消し1つに統合 |
| **先行事例** | vTaiwanの説明なし | vTaiwanの概要（台湾政府の公式協議プラットフォーム、Uber規制等での活用）を追加 |
| **国内事例** | なし | 広聴AIの活用事例を表形式で追加（渋谷区、品川区、宇多津町、東京都、選挙報道） |
| **実践ステップ** | 抽象的な6項目リスト | 5ステップに整理し、各ステップに具体的な行動例を追加（Slack招待リンク含む） |

**変更理由**: 「地域でDDを始めるには」と言いながら具体的な手順や事例がなく、読者が実際にアクションを起こせなかった。
